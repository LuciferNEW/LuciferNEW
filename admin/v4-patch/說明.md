# V4 伺服器多人同房修改版 server.py

這是把你朋友 V4 包裡的 `server.py` 改過的版本,目的:**讓兩個真人進同一房時,房主也看得到後進來的人**(解「朋友看得到我、我看不到他」)。

> ⚠️ 這份**我沒辦法在這裡測**(沒有 Windows、沒有客戶端、沒有第二台機器)。請照下面步驟換上去,照「怎麼測」實測。失敗也不會讓遊戲當掉,最壞情況就是「沒反應」,那就要走最後面的「抓封包」那段。

---

## 改了什麼(白話)

1. **記住每條連線是誰**:伺服器現在會記住「哪個帳號」對應「哪條連線」。
2. **有人進房 / 離開 / 換位 / 準備,主動推播給房裡其他人**:房主不用自己重點,名單會自己更新。
3. **解除「只能一個真人」限制**:原版房裡只要超過 1 個真人就直接報錯(它本來是設計給你一個人打電腦的)。改成:房裡 2 人以上時,不再塞電腦人,讓真人占位。
4. 全部推播都有**防當機保護**:某條連線斷了或卡住,不會拖垮整台伺服器。
5. **斷線寬限期(重要)**:連線一斷不再馬上把你踢出房間,先等 30 秒;30 秒內
   重連回來就保留你的房間與房主身分。這解掉「房主閃斷一下就被踢出自己的房、
   按設置/準備跳 `ProtocolID 116` 錯誤」的問題,也修掉重連新舊連線相撞的狀況。
6. **開打推播(對戰)**:房主按開始(指令 114)時,原本只有房主收到「對戰在
   哪」的 509 封包(位址 127.0.0.1,轉發器會改寫成你的對外 IP);現在會把這個
   509 一併推給房裡其他人,讓客人也知道對戰開在哪、能一起連進去。
7. 兩個真人同房時保留房間原本的電腦人數量(battle.py 規定開打至少要有 1 個
   電腦人),避免「開始」被擋。

**完全沒動**:登入、商店、扭蛋、背包、存檔、對戰啟動流程。只加東西,沒刪原本的功能。

---

## 怎麼換上去(重要:先備份)

1. 先把伺服器**關掉**。
2. 到你 V4 包的 server 資料夾:
   `...\风暴战区台服V4-整合包...\server\`
3. 把原本的 `server.py` 改名成 `server.py.bak`(這就是備份,出事就是把它改回來)。
4. 把這份 `server.py` 複製進同一個資料夾。
5. 重新用面板或原本的方式啟動伺服器。

> 如果啟動後 log 立刻報錯、或連登入都進不去 → 代表這版有問題,直接把 `server.py.bak` 改回 `server.py` 就回到原狀,然後把 log 貼給我。

---

## 怎麼測

1. 你和朋友都連上同一台伺服器(透過你設的對外 IP / VPN)。
2. **你**建一個房間(自由對戰那種)。
3. **朋友**進你的房間。
4. 看**你的畫面**:朋友的名字有沒有出現在房間名單裡?
   - ✅ 出現了 → 這版成功,房間同步搞定(接下來才是測「按開始能不能一起進對戰」)。
   - ❌ 還是沒出現 → 代表你的客戶端**不吃**我主動推的名單封包(109)。這不是改不好,是少了「客戶端認得的進房通知封包」那塊。走下面「最後一塊」。

---

## 最後一塊:如果房主還是看不到人(要你朋友 / 抓封包幫忙)

你的客戶端收到「有人進房」時,是靠某一個**特定封包指令**才會刷新名單。這個指令目前沒被破解出來。我推的是 109(名單本身),如果客戶端只認某個「事件通知」指令,就要先知道那是幾號。

**要問你朋友的 3 件事:**
1. 他的 V4 包,**有沒有試過兩個真人進同一間房、而且互相看得到**?
   - 如果「從來沒成功過」→ 代表這功能他也沒做出來,不是你設定問題。
   - 如果「有成功過」→ 問他當時是怎麼弄的(改過哪個檔?哪個設定?),這是最快的捷徑。
2. 他的 server 資料夾裡,除了 `server.py`,有沒有 `battle.py`、`wire.py` 以外提到「room / member / join / broadcast / notify」的檔?
3. 他知不知道「有人進房」客戶端是收哪個 protocol 編號?

**如果要抓封包(進階,可之後做):**
- 在「有成功顯示」的環境下(例如正常官服、或他成功的設定),用 Wireshark 抓 28080 埠,看朋友進房的瞬間,伺服器往房主那條連線送了哪個 command 編號的封包。
- 把那個編號跟內容給我,我就能把推播從 109 換成正確的那個。

## 技術備註(給懂的人看)

- 新增 `Lobby.connections: {usn: (writer, encrypted)}`,由 `serve_client` 在每次 handle 後維護,斷線時於 `finally` 清掉。
- 新增 `Lobby.roster_packets(number, encrypted)`:把原本 109 handler 的名單打包邏輯抽出來共用。
- 新增 `Lobby.broadcast_roster(number, exclude)`:對房內其他成員的連線推送 109 名單,逐筆 `try/except`。
- 觸發點:`106`(進房)、`107`/斷線→`leave()`(離開)、`111`(換位)、`113`(準備狀態)。
- `configure_local_bots`:房內真人 >1 時不再 `raise`,改為清空 AI 數量並 return。
- 未改的已知限制:指令 `161` 仍回傳寫死的 `127.0.0.1`(對戰位址),實際開打仍是 P2P,需靠對外 IP 轉發。這版只解「房間名單同步」,不解 P2P 連線本身。
